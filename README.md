# 词语领地

朋友之间联机玩的词语接龙 × 领地经营游戏。接词成链、连链成地，在**扩张**和**加固**之间取舍。

## 玩法

1. 房主创建房间，把 4 位房间码告诉朋友（2–6 人）。
2. 开局前房主选定本局规则：允许的关系类型、是否允许专有名词、解释最少字数、回合时长、行动点、回合数、质疑次数。
3. 系统给出几个起始词。玩家轮流行动，每回合有有限行动点，可以：
   - **接词**（1 点）：点击场上任意词，接出一个有关联的新词，并写明关系解释；
   - **加固**（1 点）：让自己的一条连接免疫质疑；
   - **结束回合**。
4. 其他玩家可以在对方回合内**质疑**某条未加固的连接（次数有限）。由房主（涉及房主的词、或房主离线时，顺延给其他在线玩家）**依据开局选定的规则**裁定——不靠模型随口判断。质疑期间回合计时暂停。暂时没有在线的裁定者时无法发起质疑（不扣次数），等有合格玩家在线后再试。
5. 质疑成立：该词被拆除，**未加固的下游词级联倒塌**；加固过的下游成为新的领地根。
6. 所有人用完回合后结算：每个词得 `1 + 深度` 分，加固 +1，最长链 ×2 奖励。长链收益高，但关键连接被拆会拖累整片领地。

## 掉线托管

玩家**掉线**或**回合计时超时**时立即进入**系统托管**，避免一个人卡住整局，重连后控制权原样回到本人手里：

- **掉线即托管**：掉线瞬间若是行动玩家，**其回合计时立即暂停**（不会被超时跳过，挂着等本人回来）；若他正好是待裁定质疑的裁定者，裁定权当场移交给在线、非托管的合格玩家。
- **超时即托管**：回合倒计时走完而本人未操作，系统进入托管并**代为结束该回合**（与旧版"超时自动跳过"一致，但会在回放里标明是托管代过）。
- **轮到仍离线的托管玩家**：托管直接**代为空过该回合**，不让无人在线的对局空等一整段计时；在线（只是上一回合超时挂起）的玩家轮到自己时**自动收回**控制权。
- **托管期间不发起、也不裁定质疑**：托管玩家不能发起质疑（服务端拒绝），也不会被选为裁定者——即便他其实还连着线（超时挂起），裁定一样顺延给在线的活跃玩家。暂时没有在线、非托管的合格裁定时，质疑无法发起（不扣次数）。
- **重连立即收回**：凭 token 重连的瞬间清掉托管标记；若其回合计时正因托管暂停，用**暂停点的剩余时间**恢复倒计时（不是重置成一整个新回合）。
- **全过程可回放**：进入托管（掉线/超时两种原因）、代为结束回合、裁定权移交、重连/轮到自己收回控制权，都作为带语义标记的关键事件写进事件日志，在回放进度与关键事件列表里可点击回看（托管 / 收回 / 移交）。
- 托管是**本次在线会话**的临时处置，`autoPilot` 标记不落盘、不跨服务器重启：重启后所有玩家按普通离线处理（保留座位、凭 token 重连）。但**暂停点的剩余时间会随房间保留**——质疑暂停 / 托管暂停的回合重启后仍是暂停态（不会被重置成完整一回合、也不会用重启前的旧时间戳立即超时）：待裁定质疑保留到裁定结束按原剩余时间恢复；托管暂停等行动玩家重连时用原剩余时间恢复；离线裁定者的裁定权在任一合格玩家重连时移交。只有重启时正在正常倒数（既无待裁定质疑也无暂停剩余）的回合才重新挂上一段完整计时。

## 主题词包与主题开局

首页点**我的词包**即可围绕一个主题准备起始词候选：每个词包有**名称、主题说明和候选词列表**（至少 3 个、最多 60 个，每词 1–12 字），支持随时新建、编辑、删除。词包默认只保存在**本浏览器**（localStorage，`wt_packs`）。

- 建房后，**房主可在大厅选择一个词包**（或保持默认词池）；选择后词包内容作为快照进入房间状态，**所有玩家开局前都能看到主题与候选词**。
- 开局从候选词中**不重复抽取**起始词（候选词不足开局数时有多少抽多少）；未选用词包时仍从内置默认词池抽取。
- 词包与规则一样只能在大厅阶段更换；游戏中途不可更换。删除本机词包不影响已选用它的房间（房间里是快照）。

### 词包分享码

想把词包给朋友用时，在词包列表点**分享**：生成一串 **8 位分享码**（形如 `ABCD-EFGH`，不含易混的 0/1/I/O），词包内容同时作为**快照存到服务器**（`data/shares.json`，与房间存档解耦、独立落盘）。

- 朋友在「我的词包」页**凭分享码导入**，词包存进自己的本机词包（带来源标记防重复导入），**建房时与自建词包完全一样**在大厅选择。
- 分享码是**公开只读**的：任何人拿到码都能导入，无需加入房间、不需要好友关系；码不暴露作者身份之外的任何信息。
- 一个词包的分享码固定不变：词包内容修改后在分享弹窗点**更新分享内容**（或再次点分享），**沿用原码**覆盖服务器快照，之后导入的始终是最新版本。
- **作者可随时取消分享**：取消后该码立即作废，再导入会提示"分享码无效或已被作者取消"；已经导入到朋友本机的词包是独立副本，不受影响。
- 取消分享的权限与赛季战绩同一道身份凭据：分享/取消随请求带上本机身份密钥，服务端单向派生出作者 pid，**只有作者本人能取消自己的码**（别人即使看到码也无法作废它）。
- 进入「我的词包」页会向服务器拉取**我的分享列表**并与本机映射（localStorage `wt_pack_shares`）对账：在另一台设备上分享的码也会列出，本机词包已删除但分享仍有效的码会单独出现在「其他设备上分享的词包」区，可复制码或直接取消；服务端已取消的码自动从本机清掉。
- **跨设备自动认领**：若本机的一份导入副本（带来源标记）其实就是当前身份在另一台设备上分享的同一个词包，对账时把它的本机 id 认领回作者稳定 id，分享码徽标、更新与取消全部合流，不再被当成"一份导入副本 + 一条跨设备分享"两件东西。
- **跨设备更新不分裂码**：在装着导入副本的设备上点更新分享，请求会带上原码，服务端校验码确实属于本人后覆盖同一条分享（保留原 packId），绝不会再生成第二个码；码不属于本人或已失效时该提示被忽略，按普通新分享处理（不能借提示覆盖别人的码）。
- 编辑导入来的词包**不会丢掉来源标记**：改过内容后同一来源仍按来源去重，不会被再次导入成第二份副本。
- 分享不随本机词包删除而失效（删除词包时会提示），要彻底作废请在词包页取消分享。

### 交流广场

分享码是一对一私下传递；**交流广场**则是全服公开的词包集市：在「我的词包」点**发布到广场**，词包快照即对所有人公开（独立落盘 `data/plaza.json`，与房间/赛季/分享码解耦）。

- 首页点**逛逛广场**进入：列表按**热度**（订阅人数）排序，也可切换**按最新**；支持按名称/主题/候选词**搜索**（覆盖全部候选词，列表只把前几个词展示为预览）、按主题下拉**筛选**（主题来自广场上实际出现的词包，热门主题在前）。
- 每个条目展示名称、主题、词数、候选词预览、发布者昵称与订阅数；看到喜欢的点**订阅到本机**，词包即存入自己的本机词包（带来源标记防重复订阅、跨来源内容判重），**建房时与自建词包完全一样**在大厅选用。
- 同一身份重复订阅不重复计热度；无有效身份的订阅不计数（仍能拿到词包）；**作者本人订阅自己的发布也不计热度**（发布即代表拥有）。
- 发布者随时可**下架**：在词包页（或广场里自己那条目上）点下架，词包立即从广场消失，其他人无法再搜索和订阅；已订阅到本机的副本不受影响。下架失败（如别的设备已先下架）会自动重新对账清掉本机残留。下架权限与赛季战绩同一道身份凭据，**只有发布者本人能下架自己的词包**。
- 同一词包编辑后再次发布**沿用原条目**覆盖快照，订阅数与发布时间保留；进入词包页会向服务器拉取**我的广场发布**并对账，其他设备上发布的词包会单列在「其他设备上发布的词包」区，可直接下架；对账时若发现本机订阅副本就是自己在另一台设备上发布的同一个词包，会自动**认领**回稳定 id（徽标/更新/下架合流），在装着订阅副本的设备上更新发布会带上原条目 id，服务端校验归属后覆盖同一条目，绝不分裂出第二条。
- 编辑订阅来的词包**不会丢掉来源标记**：改过内容后同一条目仍按来源去重，不会被再次订阅成第二份副本；名称与候选词完全相同的词包（哪怕来自分享码等别的渠道）在广场上直接显示"已在本机"，不再给订阅入口。

## 观战

没挤进对局的朋友也能只读看完整场：首页输入 4 位房间码后点**观战**，服务器分配临时观战身份（不占 2–6 人名额、不进回合顺序）。

- 大厅阶段可观战看玩家与规则；对局开始后持续收到玩家、词链、回合、计时与质疑状态推送。
- 观战者**只读**：不能接词、加固、质疑、裁定、修改规则或开始游戏（服务端双重拦截）。
- 刷新页面可凭 token 恢复观战；断线超过 60 秒自动退出，重新进入即可（服务器未重启时有效）。
- 对局**结束后观战会话即结束**：刷新页面不再自动恢复旧观战，回首页重新输入房间码即可看结算与回放；玩家凭 token 重连不受影响（要回来看结算）。结束的房间落盘时也不保留观战者与观战 token。
- 服务器重启会销毁全部连接：玩家保留座位、标记离线，凭 token 重连恢复；观战者是临时只读身份，恢复房间时会被**立即清出**（名单不残留、名额不虚占、旧 token 作废），重新输入房间码即可继续观看，不会再撞上"观战人数已满"。
- 对局结束后观战者随玩家一起进入结算，并能打开同一份局面回放。

## 跨房间赛事

把分散在**不同房间**里的朋友拉进同一张单败淘汰表：首页进入**赛事大厅**，**房主创建赛程**（设定赛事名称、报名截止时间与每个对阵房间沿用的对局规则），任何人凭本机身份**报名**；截止后**自动抽签分组**、按 2 的幂补**轮空（bye）**，随后逐轮在专用的对阵房间里决出晋级者，直到产生冠军。赛事状态独立落盘在 `data/tournaments.json`，与房间/赛季解耦。

### 赛程与报名

- **身份**：报名/创建/进入对阵都用赛季同一把本机密钥（`pid = sha256(pidSecret)`，服务端单向派生），同一身份只能报一次名；只有持密钥的本人能进入自己的对阵座位。
- **报名截止**：到点自动截止（也可由房主**提前开赛**）；满足 2 人即抽签开赛，不足 2 人则赛事自动取消。报名截止前可退出；截止后报名通道关闭。
- **抽签与轮空**：报名数不是 2 的幂时向上取整到最近签位（最多 64 人），多出的名额作为轮空**均匀撒在第一轮**（保证每场至少一名真人，不出现"双轮空"幽灵场次）；轮空者直接晋级。选手随机分配**种子序号**，种子用于平局/超时的兜底破平。

### 对阵房间与自动晋级

- 每轮选手从赛事详情点**进入我的对阵**：服务器为该场**惰性开一个普通 2 人游戏房间**（赛事房间无个人房主，规则沿用赛事快照，任何人不能改），核验"持密钥者必须是本场参赛选手"。**两人到齐自动开局**；普通"凭房间码加入"路径对赛事房间关闭（防止路人占座/冒名），但仍可**观战**。
- 对局结束按**房间胜者自动晋级**、负者淘汰，胜者写入下一轮对阵；下一轮双方到齐后该场转为可进入。决赛胜者成为**冠军**，并按淘汰轮次生成最终名次（决赛负者第 2、半决赛负者并列第 3……）。
- **赛季战绩自动回写**：每个对阵房间就是一局普通对局，结束时走既有的"逐局计入索引 + 防抖落盘 + 启动补记"链路计入赛季——弃权/重赛等没有实际对局的不产生场次，平局/重赛的每一**真实对局**都照常各计一场，赛事本身不重复记账。

### 弃权、超时与重赛

- **弃权（forfeit）**：对阵在等待开赛（双方尚未到齐开房间）期间，选手可主动认输，对手直接晋级；房间一旦开局（live）就不能再弃权，对局中的放弃由回合超时托管/打完自然判定。
- **超时未到（walkover / noshow）**：每场对阵有入场等待时长（默认 10 分钟，`WT_MATCH_WAIT_MS`，最小 60 秒）。到期只来一人 → 到场者获胜、未到者记 noshow；两人都没到 → 种子靠前者兜底晋级（保证对阵树不中断）。已开的等候房间随之退役。
- **平局（tie）**：词语领地可能平分。决赛/任意轮出现平局时，该场旧局**作废（void）但仍是计入赛季的真实对局**，并自动安排一场**重赛**；连续平局到第 3 场仍平，则由**种子靠前者**按 tiebreak 晋级。
- **异常重赛（replay）**：房主可在**下一轮公示/开打之前**宣布某场作废重赛（同一条场次链最多 3 次），胜者沿新房间重新产生、父节点进料改指向新场次；对**决赛**重赛会回滚冠军与名次、双方重新进入，重赛打完再产生新冠军。下一轮已公示（选手可进入）或已开赛则拒绝改赛。

### 一致性与恢复

- 对阵房间是普通房间，赛事↔房间用房间码反查索引关联；对局结束、房间清理、服务器重启三个接缝处对账。重启时若某对阵房间已结束但赛事回写未落盘（防抖窗口内停机）会**补回写**；房间丢失而对阵仍在等待/进行则退回"可进入"重新开房，对阵不会永久挂住。
- 完赛/取消的赛事超过保留期（默认 7 天，`WT_TOURNAMENT_TTL_MS`）连同对阵树清除；对局战绩早已独立计入赛季，删赛事不影响排行榜。所有写盘走原子写（临时文件 + fsync + rename）。

## 历史与战绩

首页自动列出本浏览器参与过的对局：已结束的显示胜负、名次与得分，并汇总场次/胜场/胜率；进行中或大厅中的房间也会列出，方便中途回来。

- 原理：每加入一个房间，客户端把该房的玩家 token 存在本机（最多 30 条）；首页凭这些 token 向服务器换取战绩摘要，失效记录（房间已删/数据已清）会自动清掉。
- 点「进入 / 回看」即凭对应 token 重返房间：进行中回到对局，已结束回到结算面板（可打开回放）。
- **已结束房间有保留期（默认 7 天）**：结束超过保留期的房间，服务器会连同整份回放日志与该房全部 token 一起清除，避免存档只增不减；首页历史里对应的失效条目会在下次刷新时按上面的机制自动消失，旧 token 再重连/观战也会被拒绝。正在线看结算或回放的连接不会被打断，等所有人断开后的下一轮清理才删除。保留期可用环境变量 `WT_ROOM_TTL_MS` 调整（清理周期 `WT_ROOM_PRUNE_INTERVAL_MS`，默认每小时一次，服务器重启时也会先清一轮）。
- **删房前先确认战绩已落盘**：房间清理不会只凭房间里的"已计入"标记——对局刚结束时赛季文件是防抖落盘的，若这 300ms 内进程退出，标记会残留为真而赛季文件里并没有这局。赛季档案自己维护一份**跨赛季全局**逐局计入索引（`data/season.json` 的 `recordedRooms`），清理前先查索引：没查到的局先补记并**同步落盘赛季后**才删房间，任何时序下排行榜与个人页都不会丢场次；赛季切换也不清空该索引，老局不会在新赛季被再算一遍。
- **结算链路全程可恢复、可重入**：对局结束 → 计入赛季 → 落盘 →（保留期满）删房这条链路在每一步崩溃后都能自愈。
  - **启动对账补记**：服务器启动（在任何请求与赛季切换之前）会扫描全部"已结束但全局索引里没有"的房间，立即补记并同步落盘——典型场景是一局刚结束、300ms 防抖落盘窗口内被杀：重启后无需任何人重连看结算、也不必等房间过期，榜单第一时间就是完整的。
  - **内存计入 ≠ 已持久化（待持久化门禁）**：服务端单独维护一份"已计入内存索引、但尚未确认落盘"的房间集合（赛季写盘成功才清空）。启动对账/结算补记后若赛季落盘失败，这些局虽已在内存索引里（`isRoomRecorded` 为真），仍被明确标记为"未落盘"；紧接着的过期清理**不能只查内存索引**——它会强制再落盘一次，失败则整轮删房中止、房间原样保留，下个周期重试。这堵住了"对账补记只在内存、落盘失败后超期房被当已持久化删除，重启永久缺场"的漏洞。
  - **失败可重试**：防抖落盘失败带有限指数退避重试，周期任务（即使没有任何房间到期）也会重新落盘挂起的战绩；落盘成功前相关房间一直保留，恢复后补记幂等（全局索引去重），不丢战绩也不重复计分。
  - **先补记后切赛季**：启动与周期任务都按"补记漏局 → 冻结老赛季 → 开新赛季"的顺序执行，跨赛季边界后重启时，老对局先进老赛季随冻结归档，绝不被错误累计进全新赛季；切换落盘失败会连同待持久化集合一起回滚到切换前状态，下个周期惰性重试，杜绝"内存已切、磁盘未切"导致的整榜重计。
  - **删房失败即中止**：删房前补记的赛季若没真正落盘（磁盘满/权限错误），本轮清理整体中止、房间原样保留，下个周期重试——宁可房间多留一个保留期，也不"房间消失但战绩没进文件"。
  - **原子落盘**：房间/赛季/分享/广场四份存档一律走"临时文件 + fsync + rename"，任何时刻磁盘上都是完整的一份 JSON，写盘中途崩溃不会留下半个文件（半个文件会让重启丢光逐局索引、进而重复计分），rename 失败时清理临时文件不留痕；读取时若仍遇到损坏档（人工编辑/磁盘故障），先改名备份为 `*.corrupt-<时间戳>` 再从空档启动，不会静默覆盖。
  - **优雅停机**：直接运行的服务器响应 `SIGTERM`/`SIGINT`，在退出前把防抖窗口内未落盘的房间与赛季全部原子刷盘（与测试的 `stopServer` 同一路径）；刚结束就收到停机信号也不丢局。
- 观战是临时身份，不进历史；换浏览器/清缓存后历史不可恢复（与断线重连的 token 机制一致）。

## 赛季排行榜与个人战绩

玩家完成对局后，服务端会把每名玩家的本局战绩计入**公开的赛季汇总**（独立落盘在 `data/season.json`）：首页提供**排行榜**入口，任何人（无需加入房间）都能看，也能点开任意玩家的个人页。

### 赛季归档与切换

赛季按固定时长轮转（默认 30 天，环境变量 `WT_SEASON_MS`；设为 `0` 关闭自动切换）：

- **冻结归档**：当前赛季到期时整榜冻结成一帧历史赛季快照（含冻结瞬间的总分榜名次，之后不再重排），新赛季**从零重新累计**；没有任何对局的空赛季不产生归档。到期检查随周期清理（`WT_ROOM_PRUNE_INTERVAL_MS`）运行，也会在打开排行榜/个人页或产生对局结算时**惰性触发**——即便服务器长期不重启，新赛季的第一局也一定计入新赛季。
- **跨赛季不重复计分**：逐局计入索引 `recordedRooms` 是**跨赛季全局**的，不属于任何一个赛季。切换赛季只清空玩家汇总，绝不清空索引——一个房间 key 一旦计入，重连广播、重启恢复、删房补记、跨赛季任何路径都不可能再计第二遍。冻结前还会先把所有"已结束但漏记"的房间补进老赛季（例如跨边界仍在保留期内、却一直没人回看的局），冻结与开新赛季在同一档案内原子落盘。
- **平滑迁移**：已有的战绩档案（v1/v2，无赛季概念）启动时**整体升级为第 1 赛季**——玩家汇总与逐局索引原样保留、一场不重算，到期才归档；旧版无索引档案的一次性对账（只建索引不重算）保持不变。
- **个人页各赛季名次**：个人页顶部是**当前赛季**汇总（场次/胜场/胜率/平均得分/最高连锁/总分榜名次，徽章也按当前赛季进度点亮），下方「各赛季名次」逐赛季列出**总分榜名次**与赛季汇总：进行中的赛季名次实时，已归档赛季用冻结名次并标注赛季起止时间。赛季刚切换、新赛季尚未开打的玩家，当前赛季汇总为空，历史名次照常可查。
- 排行榜展示的永远是**当前赛季**；排行榜头部标注当前赛季序号与累计赛季数。

- **排行榜**支持三种排序：**总分、胜场、胜率**；点任意一行进入该玩家的个人页。平局（并列最高分）人人算平、无人算负；每个排序维度都有稳定的次级依据（如同分按胜场），名次不抖动。
- **标出自己**：打开排行榜时客户端随请求带上本机密钥，服务端单向派生出 `myPid` 随响应返回（密钥不落库）；榜内**自己那一行高亮**、昵称旁带「我」标记，列表上方**固定置顶一张"我的战绩"条**，显示当前排序维度下的**名次、总分、胜场、胜率**（切换排序随之更新），点该条即滚动定位到自己那行；尚未完成对局时条内显示引导空态。
- **昵称搜索**：排行榜上有**搜索框**，按昵称即时过滤已拉取的榜单（纯前端、大小写不敏感，不重发请求），人多时输入即定位；无命中时提示并回显搜索词。
- **个人页**汇总：场次、胜场、平局、负场、胜率、总得分、**平均得分**、**最高连锁**，以及总分榜名次与最近对局时间。
- **赛季成就徽章**：个人页在数据汇总下展示按累计对局数据**自动点亮**的里程碑徽章，覆盖**场次、胜场、最高连锁**三类（各 3 档，如 1/10/50 场、1/3/10 胜、3/5/8 连锁）。已获得的徽章进入「已获得」区（彩色图标 + 名称），未达成的在「待解锁」区灰色显示并带当前进度（如「最高连锁 4/5」+ 进度条）；标题汇总点亮数（如 5/9）。徽章是赛季数据的**读时派生**：不新增任何存档字段、不改变数据格式，历史玩家打开个人页即刻有徽章，后续对局达到里程碑后自动点亮。
- **身份与防伪**：玩家身份不是客户端自报的。本浏览器随机生成一把**身份密钥**（localStorage `wt_pid_secret`，32 字节、只存本机、永不上榜）；公开的玩家标识 `pid` 由**服务端**从密钥派生——`pid = sha256(pidSecret)`。建房/加入时客户端提交的是密钥，服务端据此算出 pid。这样只有持有某把密钥的人才能认领对应的 pid：别人即使在排行榜上看到你的 pid，也反推不出密钥、更无法把自己的对局记到你名下（旧版本客户端自报 pid 可被冒用、污染他人战绩，该路径已在服务端关闭——自报 pid 一律忽略）。换浏览器/清缓存丢失密钥后会被当作新玩家（与本地历史/收藏一致）。
- 观战是临时只读身份，不参与对局，因此不进赛季战绩；没有有效密钥的客户端对局也不会计入。
- 每个房间只计一次（赛季档案带跨赛季全局逐局计入索引 `recordedRooms`，结算广播重入、服务器重启后重连、赛季切换都不会重复累计；服务器重启恢复已结束房间时不会把旧局重新算一遍）。
- 赛季战绩与房间存档解耦：超过保留期被清除的房间只删掉回放与 token，早已累计进 `data/season.json` 的战绩一行都不会少；反过来，若某局结束时赛季文件没写成就重启，保留期清理会在删房前先凭索引发现漏记并补记落盘，场次不会随房间一起消失。旧版无索引的赛季档首次加载时会与现存房间一次性对账、只建索引不重算；旧版（v1/v2）档案首次加载时整体迁移为"第 1 赛季"（战绩与索引原样保留），到期才冻结归档。

## 战术练习

不用等朋友：首页点**战术练习**即可在本机单机练习三个固定局面，每关都写清目标与可用操作：

1. **延长词链**：2 行动点内把词链接长，体会深度分与最长链 ×2 奖励（候选词有前后置解锁关系）；
2. **保护关键连接**：只有 1 行动点加固，提交后对手自动质疑让你失分最多的目标——学会把加固花在撑着最多下游词的连接上；
3. **理解级联拆除**：选择质疑目标，一次拆掉尽量多的未加固下游，观察加固词如何截断级联、成为新根。

- 每关支持**重置**（随时回到初始局面）、**提交答案**，提交后展示双方**得分前后变化**与逐条**原因解释**（每个候选目标会拆掉几个词、失多少分、最优解是什么）。
- 通关进度保存在**本浏览器**（localStorage，`wt_practice`），列表显示「已通关 / 再练一次」；换浏览器或清缓存不保留。
- 纯前端功能，不经过服务器、不计入历史战绩。

## 个人收藏本

把赛后回看延伸成可以反复复习的词语资料：对局结束后打开**回放**，在任意一步的一条连接上点「收藏」，就把这一步的**前词、后词、关系、原解释和来源房间**一起收进首页的**收藏本**（玩家与观战者都可收藏）。

- 首页点**打开收藏本**进入：支持按前词/后词**搜索**、按关系类型**筛选**；每条可以**补充个人笔记**、随时**删除收藏**。
- **复习模式**：先只显示前词与关系，点「显示后词与解释」再揭示后词、原解释、来源房间和你的笔记，然后标记「记住了」或「还要复习」。
- 标记为「还要复习」的条目下一轮**优先出现**；列表与复习页都展示总数、已记住、还要复习、未复习的统计。
- 同一条连接（同一房间同一节点）不会重复收藏；资料全部保存在**本浏览器**（localStorage，`wt_favorites`），不经过服务器，换浏览器或清缓存不保留。

- 跨房间赛事（独立 `data/tournaments.json`）：房主创建赛程并设定报名截止与对局规则，不同房间玩家凭本机密钥报名（同一身份仅一次）；到点自动/房主提前截止，2 人以下自动取消，达标后随机抽签、按 2 的幂均匀补轮空生成单败对阵表（最多 64 人）；选手逐轮从赛事面板进入专用 2 人房间（服务端核验参赛身份、两人到齐自动开局，普通加入关闭、可观战），按对局结果自动晋级并回写赛季战绩；处理报名截止/退出、等待期弃权（forfeit）、超时未到（单方 walkover、双方未到种子兜底 noshow）、平局自动重赛（3 连平种子破平）、房主异常重赛（下一轮公示/开赛前，决赛重赛回滚冠军，最多 3 次）；最终名次、重启补回写/重开房对账、完赛保留期清理与原子落盘
